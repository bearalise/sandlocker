# Sandbox ABI 后端兼容矩阵（ADR-14）

> 本矩阵由 **ABI 契约测试套件逐后端实测生成**（PRD §10），**不引用上游文档数据代替实测**。
> 复现：`sl-node --abi-contract <预烘焙模板目录>`（人类档打印下表；`--json` 供 CI）。
> CI 由 `.github/workflows/bench.yml` 的 `abi-contract` job 逐版本跑（fc 需 `/dev/kvm`，gVisor 需 `runsc`）。

「两后端可切换」= **能力对等而非功能对等**（M2技术计划 D2）：同一组 ABI 场景两后端皆过；能力差异
**显式建模**——某后端不具某能力时，声明 `required_capabilities` 该能力的 create 在**创建期**返回
`UNSUPPORTED_BY_BACKEND`（禁止运行期静默降级），矩阵标 `unsupported-ok`（符合契约，非失败）。

## 实测矩阵（本机 WSL2，fc=Firecracker microVM / gvisor=runsc rootless）

| 检查项 | fc | gvisor |
|---|---|---|
| lifecycle（create→running） | pass | pass |
| exec（命令+退出码+输出） | pass | pass |
| fs（写文件读回一致） | pass | pass |
| clone_isolation（双实例 machine-id 互异） | pass | pass |
| destroy_clean（进程/目录/store 键零残留） | pass | pass |
| cap:pause_resume | has | unsupported-ok |
| cap:snapshot_fork | has | unsupported-ok |
| cap:prebake_snapshot | has | unsupported-ok |
| cap:gpu_passthrough | unsupported-ok | unsupported-ok |
| cap:persistent_volume | unsupported-ok | unsupported-ok |

`both_backends=true, switchable=true` → **硬出口② PASS**。

## 单元格语义

- **pass / fail**：共同场景（功能对等）通过 / 失败。
- **has**：后端注册该能力，且声明 `required_capabilities=[cap]` 的 create 成功。
- **unsupported-ok**：后端未注册该能力，声明 `required_capabilities=[cap]` 的 create 于**创建期**被
  `UNSUPPORTED_BY_BACKEND` 拒绝（契约正确）。
- **GATE-FAIL**（红线）：能力不满足却创建成功（运行期静默降级），或有能力却被拒——任一即硬出口②失败。

## 后端定位

- **fc（Firecracker microVM）**：默认后端，全 SLO 承诺对象；具 `pause_resume`/`snapshot_fork`/
  `prebake_snapshot`（→ 支持温/热池、pause/resume、快照 fork）。
- **gvisor（runsc）**：短任务高密度路径，能力集**空**（无 prebake/pause/fork）——只冷创建、无池；
  rootless（`--rootless --platform=systrap --network=none`），OCI bundle rootfs 由 `debugfs rdump`
  从模板 `rootfs.ext4` 抽取。gVisor / Kata 的 SLO 于 M3 依契约测试 + 基准实测补（ADR-14）。
