## 1. 目标

M3 交付 **v0.5~0.8 Beta**，把 M2 的「单机可用 + 性能池 + 多后端 + 用户级快照/数据面」升级为「**可集群化 + 多租户面 + 全量可观测 + 静态数据加密**」的对外可试用 Beta，并**清偿 M2 移交的四笔债**：

1. **集群化**（ADR-17）：`sl-store` 切 **etcd 实现**（窄接口 M1 已备，现 `SqliteStore` 即 MVCC 形态：revision/lease/watch/CAS/changes_since/compact）+ orchestrator **多副本 active-standby**（etcd election 选主）+ 节点心跳/租约**失联自动回收**（易失态走 etcd lease TTL）。
2. **数据面网关拆独立进程副本**（ADR-22）：M2 已把 ticket/HMAC 无状态验签 + node agent 主动外拨钉死接口边界，M3 **拆分零语义变更**——任一副本服务任一沙箱、无会话粘滞。
3. **多租户面**（FR-7.1/7.2/7.3）：API Key 体系（组织→项目→Key 作用域）+ 配额（CPU/内存/并发/存储，按项目）+ 审计（append-only）+ mTLS（M2 本地环回无鉴权）。
4. **可观测性全量**（§7.8）：Prometheus 指标 + OpenTelemetry 全链路追踪（API→调度→节点→boot→ready）+ 结构化日志转发 sink；**含只读监控看板**（Grafana 策展，骑在本项遥测之上，见 §4 D6）。

并清偿 M2 移交的**债与拉伸项**：快照加密（ADR-15，当前 vmstate/mem **明文落盘**）+ 保留期/版本钉住（ADR-16）；SLO **裸金属密度实测**（M2-Q10 顺延，需 64C/128G runner）；**域名粒度白名单 FR-3.2b + DNS 审计 FR-3.4**（ADR-20）。

出口标准（PRD M3 行）：**3 节点集群 SLO 达标；外部 5 个团队试用反馈闭环**；闸门：确认 GA 范围；**启动安全审计采购（排期通常 8–10 周）**。

> **对 PRD 的 scoped 偏离（2026-08-31）**：PRD 砍单预案第 2 项将「控制台」整体移出 V1 范围（"无任何里程碑认领，CLI 够用，留待社区/商业化"）。本计划**部分回拉**——只把**只读监控看板**提前到 M3，以支撑「外部 5 团队试用反馈闭环」（M3-Q11）的可观测体验；**控制台完整操作面（创建/销毁沙箱、API Key/配额管理）仍留 GA 后**。用「Grafana 策展 + 零自建前端」框住成本（见 §4 D6），使偏离不触发 2 人团队前端维护负担（砍单原始理由）。

> 本计划延续 M2 的 **「骨架优先·债先还」**，并新增第三条姿态 **「接口边界零返工」**：M2 已把 store 窄接口（MVCC/lease/watch/CAS）与网关无状态验签 + 主动外拨**在单机形态下就钉死为集群语义**，M3 的集群化是「填 etcd 实现 + 拆网关副本」而非重构。快照加密（ADR-15）与域名白名单（ADR-20）排到 M3 后段，**滑期即降级/移 GA**——用范围换 Beta 节奏确定性。

## 3. 范围与非范围

- **只读监控看板**（M3-Q12，PRD scoped 偏离）：Grafana 策展 dashboard + 轻量状态 datasource（沙箱/节点/池/审计，按项目过滤），骑在 M3-Q5 遥测之上，零自建前端

- ❌ **OIDC/SSO + RBAC FR-7.4**（P2）；**SNI 代理严格模式**（ADR-20 P2，面向 P3 场景）

## 4. 关键技术决策（承接 ADR + M3 新增）

> D1/D3/D5 建议锁定；**D2（Go 复审）与 D4（裸金属 runner）是 M3 两条待验证前置**，须在 W1–W2 前定。

- **D1（建议锁定）：主线 = 骨架优先·债先还·接口零返工。** 顺序：①集群骨架（etcd Store 实现 → active-standby 选主 → 失联回收 → 多节点调度 → 网关拆副本）→ ②多租户面（API Key/配额/审计/mTLS）→ ③可观测性 → ④还债（快照加密 / 保留期 / 域名白名单+DNS 审计）。
  - 快照加密（ADR-15）与域名白名单（ADR-20）排 M3 后段，**滑期即降级/移 GA**（最外层可砍项）。理由：3 节点集群 SLO + 5 团队试用是硬出口，须以「加密深度 / 域名白名单严格模式」吸收滑期，锁死集群骨架与多租户面。

- **D2（已定，2026-08-31）：维持全 Rust + 集群面异步隔离区。** ADR-3/ADR-17 的「M3 闸门复审是否转 Go 写控制面」触发点已复审——**不转 Go，维持全 Rust 单栈**（延续 M1 D3 / M2 D3）。理由：复用现有 Sandbox ABI + `Store` trait 类型，消掉跨语言内部契约；guest musl `sl-envd` 零影响。
  - **异步隔离区（架构关键）**：集群面/网关面若引异步栈（tonic/tokio），须与**同步的 builder / guest / 单机进程内路径分层**——单机模式不拉起 tokio，异步依赖仅在 `cluster` feature 下编入，async 不外溢到 Sandbox ABI 与 store 契约。
  - **W1 精化（已实现，2026-08-31）：store 侧连异步隔离区都不需要。** `EtcdStore` 走 etcd 自带的 **gRPC-gateway HTTP/JSON API**（`/v3/kv/*`、`/v3/lease/*`、`/v3/watch`），用**全同步 `ureq`+rustls**（复用 M2 OCI 依赖）打请求——**零 tokio/tonic**，`Store` trait 保持同步签名、无 `block_on`；watch 用后台线程读流转发进程内 mpsc。`cluster` feature 门控（`dep:ureq`/`serde_json`/`base64`），单机构建不拉入任何 HTTP/TLS 依赖、crate 数不回涨。**异步隔离区因此收窄为「仅 W5 网关的持久 gRPC 流」**（若届时确需 tonic）。real etcd 上 `--store-contract --etcd` 契约全过（M3-Q1 达标）。

- **D3（建议锁定）：etcd 部署形态 = 内嵌可选（k3s embedded etcd 式）+ 外部 etcd 可配。** 面向 US-3 自部署简单（`sandlocker cluster init` 内置 etcd），同时允许对接已有外部 etcd 集群。单机模式保持 SQLite + 进程内 orchestrator 无选主（零回归）。

- **D4（已定，2026-08-31）：SLO 取证 = 按需云裸金属租赁（ephemeral bare-metal，opex），打两枪用完即毁。** M2-Q10 顺延——M3 **3 节点集群 SLO 达标是硬出口，不能再「待补」**。
  - **重构：capex → opex。** 这笔债卡三个里程碑，根因是一直当成「买/常驻一台 64C/128G」（capex）；但基准是**突发负载**，改为**按小时租云裸金属**（Equinix Metal / AWS `*.metal` / Hetzner 独服 / OVH，真 KVM，非嵌套虚拟化）。工程已就位（M2 `bench-density` job + `DENSITY_MIN` gate 骨架），缺的只是 runner target——租机注册为 ephemeral self-hosted runner 或 CI 经 SSH 驱动 bench。**是配置决策，非编码决策。**
  - **两枪**：W2–W3 **单节点密度基线**（de-risk，尽早暴露口径达不达得到）；W12 **3 节点集群**出口取证（M3-Q9 密度 + M3-Q10 集群 SLO）。跑完即毁，不付闲置。
  - **口径不下调**（PRD §8.1）。**逃生口（仅预算批不下来时）**：云 VM 产方法学 + 相对分位，绝对裸金属 SLO 标「待补」+ go/no-go 升级上报——**不作为计划，只作兜底**（等于第四次 punt）。
  - **前置**：opex 预算 / 云开户须 **W1 拉动**（非周内工时），W2 前 runner 可用。

- **D5（建议锁定）：快照加密 KMS = V1 文件实现（开发级）+ Vault 插件留 GA。** 信封加密：每快照随机 DEK（AES-256-GCM，4MiB 分块独立 nonce）+ 租户 KEK 包裹存控制面（etcd）；根密钥经 **KMS 接口**，V1 文件实现为开发级，Vault 插件 P1/GA。节点**永不持久化明文 DEK**；pause 完成前 sl-envd 擦除自身密钥材料。威胁模型明示边界（防静态失窃、不防持钥节点被攻破；pause 捕获 guest 内存中一切 secret，§8.2）。

- **D6（建议锁定）：只读监控看板 = Grafana 策展 + 零自建前端，骑 W8。** 交付一套策展好的 Grafana dashboard（消费 M3-Q5 的 Prometheus 指标 + OTel 追踪链接）+ 一个轻量**状态 datasource**（暴露沙箱/节点/池库存/审计的只读查询，读 etcd/store，按 M3-Q4 项目维度过滤）。
  - 理由：PRD 砍单预案第 2 项砍控制台的原因是「2 人无法维护前端」。Grafana 路线**不自建前端、无新前端工具链**，把看板降解为「遥测 + 一个只读 datasource endpoint」，落在 M2 D5「精简依赖」哲学一侧（Grafana 为运维侧外部组件，非编入产品二进制的依赖）。
  - 边界：**只读**——不含创建/销毁/Key/配额的写操作（那是控制台完整操作面，留 GA）。看板随多租户面（M3-Q4）做项目过滤，无鉴权则拒。

- **接口零返工策略（M3 新增，架构关键）：先证双实现等价，再上集群。** W1 先让 `EtcdStore` 通过与 `SqliteStore` **同一套 store 契约测试**（M2 `--abi-contract` 模式复用），**再**接 orchestrator active-standby——避免「先集群再补 store 语义差」的返工。网关拆分同理：M2 已钉死无状态验签 + 主动外拨，W5 是「进程内模块 → 独立进程」的部署变更，非协议变更。

**W2 落地（已交付，2026-08-31）**：① 后端无关**选主** `sl_store::election`（CAS+lease，`--election-reconcile [--etcd]`：双竞选者 → 单 leader + resign failover + 无双主，真 etcd live 验证）；② `cluster init` **迁移** `migrate_all`（`--cluster-init --store <sqlite> --etcd <ep>`，SQLite→真 etcd 全量迁移 live 验证）。**接缝（ADR-17）**：选主刻意不做全局 `lease_sweep`（避免与 orchestrator 抢扫沙箱租约，有回归护栏测试）；**单机 SQLite 无选主、恒 leader**（serve 恒 true、reaper 照跑、零回归），真 active-standby 待 W3/W4 Orch 迁 etcd 后由 `election` 驱动（reaper 门控已就位）。

**W3 落地（已交付，2026-08-31）**：后端无关**节点心跳 + 失联回收** `sl_store::cluster`（易失态走 lease TTL：`node/<id>` 挂心跳租约；失联 → 租约过期 → 键消失 → leader 回收其名下沙箱撤租连删 meta/state/node）。沙箱创建写归属键 `sandbox/<sid>/node`（同租约）。**安全护栏**：节点绝不回收自己名下沙箱（只回收别的死节点的，防心跳偶发失效自戕）。`--node-reclaim-reconcile [--etcd]`（心跳 + 孤儿回收 + 存活不动 + 护栏，真 etcd live 验证）。serve() 接入：本节点自注册 + 心跳线程 + 创建写归属键 + leader reaper 回收（单机恒 leader、恒存活、无孤儿、护栏防自戕，零回归）。

**W5 落地（已交付，2026-08-31，集群化收尾）**：数据面网关**拆副本的核心前提**——把 ticket 的 HMAC secret 与一次性 nonce 从「每进程随机 + 进程内 HashSet」升级为 **Store-backed 共享**（`Gateway::new_shared`）：secret 经 `cluster/gw_secret` CAS 收敛（首写者定、余副本读同值）→ **任一副本可无状态验签任一副本签发的 ticket**；nonce 经 store CAS 消费（挂租约按 exp 自动清理）→ **一次性跨副本生效**。serve() etcd 模式启用（单机沿用进程内随机，零回归）。`--gw-cluster-reconcile [--etcd]`（A 签 B 验 + 一次性跨副本 + 篡改/过期拒，真 etcd live 验证）。**这坐实 M2 钉死的接口边界「拆分零语义变更」**。**W5 剩余（诚实标注，移 W10 或后续）**：真正独立 `sandlocker-gw` 进程 + **node-agent 主动外拨持久流**（节点零入站）+ 跨节点数据转发（网关在副本 X、沙箱在节点 Y 时的 exec/logs/port 中继）——ticket 层已可拆，数据面传输协议（多路复用持久流）是较大工程,单列跟进。

**W5 余项落地（已交付，2026-08-31，数据面网关真拆分 → M3-Q3 达成）**：补齐 W5 当时诚实标注的三项缺口——**独立 `sandlocker-gw` 进程** + **node-agent 主动外拨持久流** + **跨节点数据转发**，并顺手收掉 W6 的 **mTLS** 余项。

- **形态（对计划措辞的偏离，如实记录）**：原文写「多路复用持久流」，实际取**预拨连接池式反向隧道**——节点对网关预拨 `--gw-pool`（默认 8）条**空闲持久连接**停驻，网关按需借一条、写一行 `OPEN {已验签 ticket}`，此后该连接为这条逻辑流**独占**的字节管道。放弃帧级多路复用的理由：多路复用要让多个逻辑流共享一个 rustls 状态机（同步栈下多线程并发读写，记录序号一旦错序整条连接解密失败），收益仅是省连接数；预拨池让**每条流单一属主**，无共享状态机。**M3-Q3 的三条判据（任一副本服务任一沙箱 / 无会话粘滞 / 节点零入站）两种形态等价满足**，故取更不易错的一种。
- **补拨时机（设计要点）**：补拨发生在**开流的瞬间**而非流结束之后——否则空闲余量被流的时长绑住，`--gw-pool` 个 PTY 会话就能把节点数据面焊死。达 `--gw-max-streams`（默认 256）时改为就地串行处理，对网关形成背压而非无限开线程。
- **全双工**：M3-Q3 点名 PTY，PTY 是交互式双向流，中继必须全双工；而 rustls 同步 `StreamOwned` 不能被两线程同时读写。`dataplane::Duplex` 手写同步全双工封装：阻塞 socket 读在 conn 锁**之外**（读不挡写），写方向以锁序 `conn → sock_w` 保证 TLS 记录落 socket 的顺序 == 状态机产生的顺序。
- **零语义变更（ADR-22 的兑现）**：节点侧走的是**与进程内网关同一段** `serve_gw_ticket`——网关验签后把已验签 ticket 下发，节点不重复验签（nonce 已被一次性消费，再验必失败），采信根据是 mTLS。
- **mTLS（收 W6 余项，FR-7.1）**：节点接入端口**强制**客户端证书（`WebPkiClientVerifier`）。rustls 钉 `default-features=false + ring`——避开默认 aws-lc-rs（cmake + 大量 C），复用 ureq 已在用的同一 provider，**新增 crate 仅 `rustls-pemfile` 一个**。默认**不放行明文**：漏配证书报错而非静默降级，明文须显式 `--gw-insecure`。
- **跨节点控制面**：`/v1/.../exec|logs|files` 与 `/v1/.../exec/stream` 在沙箱不属本节点时，由本副本自签 ticket 经 `--gw-url` 转到 owning 节点（响应逐块回灌，流式 NDJSON 不被缓冲）。
- **对账**：`--gw-dataplane-reconcile [--etcd] [--gw-tls-*|--gw-insecure]` 起真网关 + 两个真节点代理，验 ①按归属路由 ②无粘滞（交替服务两节点沙箱）③一次性 ④篡改拒 ⑤未知沙箱 404 ⑥未接入节点有界 503 ⑦分块响应**逐块**到达（证明全双工未整体缓冲）⑧明文连接不得被 mTLS 端口收编。`scripts/verify-gw-dataplane.sh` 另以 openssl 造证书跑活证：无客户端证书 → 握手被拒；合法证书 → 握手成立（对照组）。**明文 + mTLS × SQLite + 真 etcd 四组合全过。**
- **过程中修掉的真 bug（只有跑起来才会暴露，记以备忘）**：① TLS 握手的 `complete_io` 会把紧随其后的应用数据（节点问候行）一并读进 rustls 内部缓冲，而 `do_read` 原本只在**新 socket 数据到达后**才抽明文——于是问候行永远取不出、连接全部超时不入池、网关一律 503。改为**先抽干状态机明文再考虑阻塞收包**。② TLS 配置原本**每条连接重建一次**（重解析 PEM/私钥），首拨风暴直接把握手拖垮；改为起代理/起网关时预构建一次共享。
- **W5 余项剩余（诚实标注）**：**控制面**路由（pause/resume/fork/destroy/keepalive/expose）对**非本节点**沙箱仍不可用——那是 W4 多节点调度遗留的缺口，不在数据面范围内，单列跟进。

**W9 落地（已交付，2026-08-31，快照信封加密 → M3-Q6 达成，【还 M2 债】）**：ADR-15 落地——KMS 根密钥 → 租户 KEK → 每快照 DEK 的三级信封，4MiB 分块 AES-256-GCM。

- **加密只能包在 Firecracker 外面（架构约束，先说清楚）**：FC 的快照是它自己读写的（`PUT /snapshot/create` 由 FC 落盘，`PUT /snapshot/load` 又由 FC 直接 `mmap` 那个 `mem` 文件做惰性缺页），FC 不认识密文、也没有插自定义存储层的口子。所以本周做的是**落盘后加密 / 恢复前解密**：`pause` 后把 `vmstate|mem` 封成 `.enc` 并抹掉明文；`resume/fork` 前解出明文交给 FC。
- **由此界定的边界（如实记录）**：受保护的是**暂停态快照**——即节点关机后仍留在盘上的那份状态，正对 ADR-15「防静态失窃」的口径。**运行中**实例的 `mem` 必须是明文（FC 全程 mmap 它），这不构成额外暴露（运行中的内存本来就在宿主 RAM 里）。曾考虑把解密目标放 tmpfs 以求「明文永不落盘」，代价是每实例多吃一份等量 RAM（512MiB 量级），直接冲垮密度硬出口（M3-Q9 ≥200/节点），故不取。
- **密钥层级**：根密钥（**文件 KMS，开发级**，D5；Vault 插件仍列 P1/GA）→ 租户 KEK（每项目一把，**以密文**存控制面 `kek/<project>`，首用时 CAS 收敛，与 W5 的 `cluster/gw_secret` 同一手法）→ 快照 DEK（每快照随机，**以密文**存快照头）。**节点不持久化明文 DEK/KEK**，明文只在内存里活到一次加解密结束（`Key` 的 `Drop` 清零）。
- **容器格式 `SLSNAP1`**：头部（magic/版本/算法/块长/明文长/kek_id/被包裹 DEK）**全字段绑进每块 AAD**——头虽明文但改一个字节即全块解密失败。块 `i` 的密文起点是纯算术 `header_len + i*(chunk_size+16)`，**支持随机读**，将来接 userfaultfd 懒加载（P2）不必改格式；这正是 ADR-15 选分块 AEAD 而非整文件 AEAD 的理由。nonce = `0u32||be64(i)`，DEK 每快照随机故 (DEK,nonce) 全局唯一。
- **guest 侧擦密钥**：新增 `Request::WipeKeys`，host 在 `PATCH /vm Paused` **之前**下发，sl-envd 覆写并删掉自己签发的 `/etc/sl-session-key`。无损——resume/fork 必经 `Reinit`，那里本就换发新会话密钥。边界：只擦 sl-envd **自己的**密钥材料，**pause 仍会捕获 guest 内存中当时存在的一切 secret**（PRD §8.2），用户侧凭据轮换须文档指引。
- **fail closed**：密封失败 → 抹掉明文与半成品 → 把 VM 放回运行态（沙箱不丢，只是这次 pause 失败）→ 如实报错；连放回运行态都失败才杀。绝不在密封失败时把明文 guest 内存留在盘上。
- **依赖**：AEAD 用 **ring**——它早已在依赖树里（ureq → rustls → ring），故**零新增 crate**（`Cargo.lock` 逐条比对确认），守 M2 D5「精简依赖」。
- **显式开关**：`--snap-kms-key <文件>` 给了才启用（`--snap-kms-init` 生成 0600 根密钥，拒绝覆盖既有文件）。不静默生效——加密改变快照落盘格式，与既有明文快照不兼容，何时切由部署方决定。**建议 GA 默认开启**。
- **对账**：`--snapcrypt-reconcile [--etcd]` 走 pause/resume 真正调用的 `seal_snapshot`/`unseal_snapshot` 与真正的 KEK 解析路径，验 ①密封后明文消失/密文可解回 ②密文里搜不到明文特征串 ③控制面搜不到明文 KEK ④快照文件里搜不到明文 DEK ⑤篡改一字节即拒且不留半成品 ⑥项目 A 的快照用项目 B 的 KEK 解不开 ⑦KEK 重复解裹一致 ⑧换根密钥解不开 ⑨只解第 i 块与整解切片一致。SQLite + 真 etcd 双后端全过；另有 9 项加密单测（跨块往返/空文件/篡改头部/随机读/每快照新 DEK 等）。
- **W9 剩余（诚实标注）**：① **端到端**（真 FC pause → 密文落盘 → resume）依赖 KVM，随 `--q5-reconcile` 一类在 KVM 机器上取证，本周未在无 KVM 环境跑到；② **Vault KMS 插件**按原计划留 P1/GA，V1 文件 KMS 的根密钥与密文同机——**只防盘被拷走，不防节点被攻破**，威胁模型已在模块头与部署指南明示；③ 覆写抹除在 CoW/日志式文件系统与 SSD FTL 之下不保证物理块被擦，属纵深防御而非保证。

**缓冲说明**：**W1–W5（集群化 + 网关拆分）是 M3 最大不确定块**（etcd 合龙、选主/回收第一次集群化、网关从进程内拆独立副本）。若滑期：优先保「3 节点集群 SLO 达标 + 单机 SQLite 零回归」；网关拆分若受阻，退到「进程内网关 + 无状态验签已就位、拆分延后」的最小集群形态（M2 边界已钉死，返工小）。**只读监控看板（W8，scoped 偏离）**为**第一顺位可砍项**（W8 遥测若超载即回退 PRD 原判「移 GA」，不影响硬出口）；其次 **快照加密（W9）深度**与**域名白名单严格模式（W11）**为最外层可砍/降级项（域名白名单主机制 DNS 劫持保留、SNI 严格模式本就 P2 移 GA）。

**前置依赖（须提前拉动，不占周内工时）**：① **安全审计采购 W1 即启动**（8–10 周排期，落在 W9–W12，与出口闸门对齐；晚启动则 GA 阻塞）。② **按需云裸金属 opex 预算/开户**（D4，已定租赁路线）须 **W1 拉动**（非周内工时），W2 前 runner 可用——W2–W3 单节点基线 + W12 三节点出口；否则 M3-Q9/Q10 两条硬出口阻塞。③ **外部 5 团队招募 W1 即启动**（试用需前置环境 + 文档，反馈闭环需数周窗口）。
