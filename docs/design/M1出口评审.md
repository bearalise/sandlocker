## 1. 验证问题结论（Q1–Q9）

| # | 问题 | 结论 | 证据 |
| --- | --- | --- | --- |
| **Q1** | FC HTTP API + jailer 能否替代 config-file 路径（含 snapshot create/load） | ✅ 通过 | boot/snapshot create/load 全走 FC HTTP API（W1/W2，`fcapi.rs`）；jailer 做 chroot+cgroup+降权后拉起 FC（D1 root 档，`main.rs:8`）。rootless 开发/CI 档用 `unshare` userns 等价隔离（免 root） |
| **Q2** | 预烘焙快照 → 创建走恢复路径 P50 ≤500ms | ✅ 通过 | `--orch-bench`（10 采样，首轮 warm-up 丢弃）：**P50=114ms / P90=122ms**（≪500ms）；分段 copy 49 / api-ready 21 / load 27 / resume 0 ms。CI 门禁 `bench-restore-create.sh`（P50>500ms 即红） |
| **Q3** | ADR-12 post-restore reinit 是否消除克隆状态泄漏 | ✅ 通过 | `--clone-entropy-check`：同快照恢复两实例，machine-id / RNG / 会话密钥**三项两两必不同**（内核 vmgenid reseed + 每恢复唯一 host 种子）。CI 红线 `bench-clone-entropy.sh` |
| **Q4** | ADR-13 恢复时序是否使"策略生效前无发包窗口"构造上不存在 | ✅ 通过（结构性） | 时序：load(`resume_vm:false`，vCPU 暂停) → 策略钩子 → resume。vCPU 未运行前构造上无法发包，且策略钩子恒早于 resume。**新增探针 `bench-net-timing.sh`**（6 轮）断言每轮 `policy_before_resume=true`（余量 µs 级）→ 进 CI 红线。**注**：钩子内真实 nft allow 写入待 jailer-netns（M2，见第 5 节） |
| **Q5** | dm-thin 分层 CoW 是否正确、销毁无残留块 | ✅ 通过 | `--dmthin-reconcile`：base origin + per-sandbox thin snapshot，写不污染 base；反复销毁释放 thin 设备与独有块无孤儿。CI `dmthin` job（sudo，每 PR） |
| **Q6** | 模板构建（build-as-sandbox，ADR-19）能否走通 | ✅ 通过 | `--build examples/hello.sandlocker.toml`：`pass:true`、`signed:true`、`build_network:deny`；产出版本化(`64ad1212a112`)+内容寻址+ed25519 签名三件套(rootfs/vmstate/mem)+manifest+sig。CI `bench-light` Q6 冒烟 |
| **Q7** | nftables per-sandbox 白名单 + deny-by-default 是否正确 | ✅ 通过（后端） | `--nftfw-reconcile`：具名 netns+veth 通路取证——无策略拒绝 / 加 allow 原子放行 / 销毁删表无残留，`nft list ruleset` 可审计。CI `dmthin` job（sudo）。**注**：接进 live 沙箱出口待 jailer-netns（M2） |
| **Q8** | Python SDK + CLI 覆盖 US-1/4/7 | ✅ 通过 | `verify-sdk-e2e.sh`：US-1 create→run→取产物→空闲自毁 / US-4 模板秒级就绪 / US-7 `with` 跑测试→退出码透传→跑完即焚，均实测真 microVM 零残留。CI `bench-light` W9 e2e |
| **Q9** | SQLite 元数据 + 生命周期回收是否正确 | ✅ 通过 | `--orch-reconcile`：create/keepalive/idle 到期/TTL 硬顶/手动 destroy 每步零残留（进程/目录/sockets/store 键）+ 并发双克隆隔离 + 模板 rootfs 不可变。元数据走 `sl-store`（rusqlite bundled）。CI `bench-light` Q9 |

## 4. M2 开工闸门（结论：可进入 M2）

前置齐备：M1 全部 Q 有结论、v0.1 产物化、契约（openapi/proto）冻结为 M2 演进基线。M2 首批范围
（承接本评审第 5 节的移交）：

1. **jailer-netns 落地**（最高优先）：把 W5 nftfw 后端接进 **live 沙箱出口**（veth+NAT + 恢复钩子内真实 nft allow 写入），使 Q4/Q7 从"后端+结构性"升级为"live 端到端 gate"。
2. **allow-network 构建**：模板构建 egress（jailer-netns），支撑真「Python + 依赖」团队模板（US-4 完整形态）。
3. **keepalive 续期端点**：REST 开 keepalive（FR-1.2），SDK 补 `keep_alive`。
4. **SLO 数据裸金属化**：创建/恢复分位、密度（Q4-M0 遗留）在 64C/128G 产出 SLO 口径。

## 5. 已知局限（诚实记录，移交 M2）

- **live 网络 gate 未接线**：`apply_network_policy`（`main.rs`）在 rootless 恢复路径为**占位钩子**
  （仅记策略生效时刻，不写真 nft）——该路径 `unshare --net` 无具名 netns 句柄、无真实出口可 gate。
  Q4 因此是**结构性保证**（vCPU 暂停 + 钩子先于 resume ⇒ 无发包窗口）+ 时序探针红线；Q7 是**后端正确性**
  （具名 netns 独立取证）。二者接进 live 沙箱出口随 jailer-netns 落地（M2 首批）。
- **jailer 为 D1 root 档**：开发/CI 主路径用 `unshare` userns（免 root，NOPASSWD 白名单不含通用提权）。
  jailer chroot/cgroup/seccomp 生产档需 root 环境实证。
- **发布签名/Release 未端到端验证**：无 tag 推送、无 Actions OIDC/secrets；本地已验证构建 +
  `SHA256SUMS` + workflow 语法，cosign 签名与 GitHub Release 待首个真实 tag 在 CI 跑通（`RELEASING.md`）。
- **文档站/Pages 首启依赖仓库设置**：Settings→Pages 选 GitHub Actions 源（一次性，非代码缺陷）。
- **基座无 Python + build_network=deny**：`run` 走 busybox `/bin/sh -c`；真 Python 模板需 M2 allow-network。
- **SLO/密度数据未产**（承 M0）：开发机 7G 内存受限，须裸金属 dispatch。
