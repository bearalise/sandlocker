## 1. 目标

M1 交付 **v0.1 MVP，单机一体化**，把 M0 的"能跑通一条命令"升级为"可用的沙箱平台"：

1. **快照/恢复引擎（内部能力）**：模板预烘焙 → 创建走恢复路径，**P50 ≤500ms（无池）**。这是 M1 的心脏，也是 M2 pause/resume 用户 API 与预热池的地基。
2. **平台最小闭环**：生命周期（FR-1.1/1.2/1.3）、exec/fs（FR-2.1/2.2）、模板（FR-4.1/4.2）、Python SDK、CLI、deny-by-default + IP/端口白名单（FR-3.1/3.2a）。
3. **单机一体化**：`sandlocker up` 一条命令起全部组件（SQLite 元数据，本地文件系统快照仓库）。

出口标准（PRD）：发布 v0.1；**US-1/US-4/US-7 场景可用**；创建 P50 ≤500ms（预烘焙恢复路径，无池）；文档站上线；闸门：对照砍单预案确认 M2 范围。

## 3. 范围与非范围

**范围内**：
- 快照/恢复引擎：FC snapshot create/load、内存文件 mmap 缺页恢复（ADR-23）、全量自包含内存 + dm-thin 磁盘增量（ADR-6/25）、本地文件系统快照仓库（ADR-9）
- ADR-12 post-restore reinit（sl-envd 例程：machine-id/hostname/会话密钥换发、网络身份重配、时钟校正、vmgenid reseed 校验）+ ADR-13 恢复时序
- dm-thin 存储栈：thin pool、base rootfs 为 thin origin、per-sandbox thin snapshot 设备
- 网络：deny-by-default（结构性）+ IP/端口白名单（nftables per-sandbox table，ADR-21）+ ADR-13 恢复时序
- 模板：`sandlocker.toml` DSL（FR-4.1）+ 构建流水线（build-as-sandbox，ADR-19）+ 预烘焙快照
- 生命周期（FR-1.1/1.2/1.3）、exec/fs（FR-2.1/2.2）、SQLite 元数据（ADR-17 窄接口）
- API Server（REST/gRPC）、CLI（build/run/ps/logs/exec/snapshot/up）、Python SDK
- 基准 CI 扩展：恢复路径分位、克隆熵回归、网络时序探针

**范围外**（碰了就是范围蔓延）：
- ❌ **pause/resume 用户 API、预热池**（M2；M1 快照仅内部能力，创建即走恢复路径）
- ❌ **快照加密（ADR-15）、保留期/版本钉住管理（ADR-16）**（M2）
- ❌ **快照 fork/branch 用户 API**（M2/GA）；持久卷（GA）
- ❌ **数据面网关（ADR-22）、PTY、端口暴露 FR-3.3**（M2）
- ❌ **域名粒度白名单 FR-3.2b、DNS 审计 FR-3.4**（P1，阻塞于 14.2-4，M2）
- ❌ **JS/TS SDK、gVisor/Kata 后端、Sandbox ABI 完整抽象**（M2）；集群/etcd（M3）
- ❌ Dockerfile 子集兼容（M1 仅自定义 DSL；Dockerfile 子集列 P1/M2）

## 4. 关键技术决策（承接 ADR + M1 新增）

> M0 暴露三个硬约束，M1 必须正面处理，此处显式决策（**D1/D2 为需确认的枢纽决策**）。

- **D1（已定，2026-08-04）：切 FC HTTP API（前置条件，非选择）+ jailer 放 M1 且 W1–W2 早落 + API 客户端手写极简。**
  - **切 API 是前置条件**：快照 create 只能经 API（`PATCH /vm` → Paused，`PUT /snapshot/create`），config-file 只能从零 boot、造不出快照；模板预烘焙必须 create，故统一走 API。M0 config-file 路径退役为对照。（快照 load 或可经较新 FC 的 config-file，但 create 已逼出 API，不分叉。）
  - **jailer 放 M1，且早于 dm-thin/快照落地（W1–W2）**：真正的理由是**文件布局**——jailer chroot 使内核/rootfs/快照/vsock UDS 必须在 chroot 内，而 M1（W2–W4）正是设计 dm-thin+快照布局的时刻；推迟到 M2 会使布局返工。安全上亦是第一性需求（v0.1 即跑不可信代码，chroot/cgroup 不该缺席）。注：FC 自带默认 seccomp，jailer 加的是 chroot+cgroup+降权。
  - **FC API 客户端手写极简 HTTP/1.1-over-UDS**：仅用到少数端点（machine-config/boot-source/drives/network/snapshot create\|load/vm state），延续 M0 极简依赖风格（运行时层目前仅 libc+serde），不引重 HTTP 依赖。实现细节，W1 顺手定。
- **D2（已定，2026-08-04）：上真 dm-thin → node agent 转特权模型；功能测试走托管 runner + 免密 sudo，不自建 runner。**
  - **上真 dm-thin（ADR-23 正典）**，不用"每沙箱全量拷贝 rootfs"的免 root 替代——后者牺牲密度/秒级就绪且是必被 M2 推翻的技术债。真正逼出 root 的是 dm-thin（`dmsetup`/device-mapper ioctl 需 CAP_SYS_ADMIN，块层 CoW 无 rootless 替代）；jailer/nftables 亦特权但有回旋。
  - **功能正确性测试走 GitHub 托管 Linux runner**（提供免密 sudo，`losetup`+device-mapper 一般可用）：dm-thin 用 loopback 造 pool、nft、jailer 均可跑。**不为 M1 功能测试自建 runner**。前置：W1 先验证托管 runner 可加载 `dm_thin_pool` + `dmsetup` 建 thin pool（不通则退到一台便宜特权 runner 只跑存储集成，仍优于全量拷贝）。
  - **密度实测维持 M0 分层**：bare-metal 按需 dispatch（64C/128G），不因 D2 新增常态自建负担。
  - **M0 rootless（unshare userns）路径保留为 dev/CI-light 快车道**（exec/网络快速迭代，免 sudo 自助）；但**存储/快照带 CoW 的集成一律走特权**。两条网络搭建路径并存，rootless 那条已写好、保留成本低。
  - **本机开发内环**：配 scoped sudoers NOPASSWD（仅 `dmsetup`/`nft`/`jailer`/`firecracker`）或 node agent 作 root dev 服务；避免每命令交互输密码毁开发手感（一次性配置，文档写清）。
- **D3（已定，2026-08-04）：M1 控制面用 Rust（显式偏离 ADR-3），单机一体化为单 Rust 二进制、全组件进程内。**
  - **偏离 ADR-3 声明**：ADR-3 原定"控制面 Go"。M1 scoped 偏离——理由：2 人团队最硬约束是节奏，M1 最难的是快照引擎（W2–W4），此时再加第三门语言（Go）工具链/CI/依赖/上下文切换不划算；M1 控制面小且单机（API server + 生命周期 + SQLite store），PRD 6.2 本就说单机模式 orchestrator/gw"退化为进程内模块"；折进单二进制还消掉 node agent（Rust）与控制面之间一条内部跨语言契约，可直接共享 Sandbox ABI 类型。
  - **形态**：`sandlocker up` = 一个 Rust 二进制，api/orchestrator/gw/node agent/snapshot 引擎全进程内；sl-envd Rust；Python SDK 经契约与之解耦。
  - **护栏（框住 M3 可能的 Go 返工）**：① 契约先行——对外 API 用 OpenAPI + Protobuf 描述，SDK 与未来可能的 Go 重写都以契约为准；② 窄 store 接口（Get/Put/Watch/Txn/Lease）Rust 抽象好、SQLite 实现，M3 换 etcd（Rust 客户端或重写）边界收敛；③ 控制面逻辑模块化、不与 node agent 内部纠缠，保证 M3 若走 Go 可干净抽取。
  - **闸门**：M2（网关/ABI 到来）复审，M3（集群/etcd 真到来）最终定 Go/Rust。"M3 逼 Go"是弱强制——etcd 可作独立进程由 Rust 客户端连，内嵌 etcd 仅部署便利，故可推迟。
  - PRD ADR-3 已标注"M1 scoped 偏离，M3 复审"（2026-08-04）。
- **D4：快照模型全量自包含内存 + dm-thin 磁盘增量（ADR-6/25）**，快照不可变、树边 pause/fork 时刻形成、删除无合并语义；M1 仅用于模板预烘焙与创建恢复（fork 用户 API 在 M2）。
- **D5：预烘焙点定义（ADR-18/12）**：sl-envd 完成挂载与 vsock 就绪、start_cmd（如有）已拉起、应用代码未运行；该点前禁止初始化随机性/身份（构建器检测并拒绝违规模板）。

## 6. 风险与回退

| 风险 | 应对 |
| --- | --- |
| 托管 runner 缺 dm_thin_pool 模块（D2 前置未过） | W1 先验；不通则退到一台便宜特权 runner 只跑存储集成（仍优于全量拷贝）；功能测试**不脱离托管**是默认预期，密度维持 bare-metal dispatch |
| M1 控制面 Rust 偏离 ADR-3，M3 若走 Go 需返工（D3） | 返工有界：M1 控制面小 + 契约先行（OpenAPI/Protobuf）+ 窄 store 接口 + 模块化；M2/M3 闸门复审，届时信息更多再定 Go/Rust |
| 两语言（Rust/Python）仍需并行工具链 | 契约先行自动生成 Python SDK；运行时/控制面同为 Rust 工作区、共享类型，无内部跨语言契约 |
| ADR-12 reinit 正确性（安全关键，克隆状态泄漏） | W4 专周 + 克隆熵回归测试进 CI；预烘焙点由构建器强制检测违规模板 |
| FC 快照绑定内核/VMM 版本（ADR-16） | M1 仅内部快照、单机同版本，版本钉住/N-1/加密留 M2；本计划不承诺跨版本恢复 |
| 创建 P50 >500ms | 恢复路径分段定位（承 M0 埋点）；page cache 热为前提；不达标以分段数据决策，不下调口径 |
| 快照引擎滑期拖累整体 | W2–W4 为关键路径，其余（模板/网络/SDK）可并行；快照不通则 M1 无意义，优先级最高 |
