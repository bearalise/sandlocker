## 1. 目标

M2 交付 **v0.2~0.4 Alpha**，把 M1 的「单机可用闭环」升级为「有性能池 + 可插拔后端 + 用户级快照/流式面」，并**先清偿 M1 移交的四笔债**：

1. **live 网络（真出口 gate）**：把 M1 只做到「后端正确 + 结构性时序」的网络，接进 **live 沙箱真实出口**（jailer `--netns` + veth/NAT + 恢复钩子写真 nft allow），使 deny-by-default + 白名单在真流量上生效。
2. **预热池 → 池命中 P50 ≤100ms**（**硬出口①**）：温池（默认）+ 热池（可选，默认 0），承接 M1 恢复引擎（ADR-23）。
3. **Sandbox ABI 抽象 + gVisor 第二后端可切换**（**硬出口②**）：能力模型为 ABI 一等公民（ADR-14），两后端由契约测试套件验收。
4. **pause/resume 用户 API + 数据面**：FR-1.4 用户级快照；数据面网关（ADR-22，单机进程内）+ PTY + 端口暴露（FR-3.3）。

出口标准（PRD M2 行）：**池命中 P50 ≤100ms；两个后端可切换**；闸门：对照砍单预案确认 M3 范围。

> 本计划的主线姿态是 **「骨架优先·债先还」**（见 §4 D1）：先还 M1 债与打通 live 网络/性能池/多后端骨架，快照加密（ADR-15）与 JS/TS SDK 排到 M2 末尾，**滑期即移 M3**——用范围换节奏确定性，是 2 人 12 周超载下的显式取舍。

## 3. 范围与非范围

**范围内**：
- **live 网络**：jailer `--netns` 真 netns + veth/NAT 出口 + `nftfw::Sandbox::ensure` 接进恢复钩子（M2-Q1）；allow-network 构建三档（M2-Q8）
- **OCI 镜像当 rootfs 来源**（ADR-18，M2-Q12）：`from` 字段支持 OCI 引用 → ureq+rustls 手写薄 registry v2 协议拉取/解包/flatten→ext4 + OCI config（Env/WorkingDir/Cmd）物化；官方 Python 镜像作基座（与 M2-Q8 allow-network 构建咬合出真 Python+pip 模板）。**注：这是「OCI 镜像作 rootfs 来源」，≠ 范围外的「OCI Runtime 独立形态」**
- **预热池**：温池（默认，快照预置本地 + page cache 热 + 元数据预载）+ 热池（可选，默认 0，已恢复 paused VM），ADR-23（M2-Q2）
- **Sandbox ABI + 能力模型**（ADR-14）：FC 后端重构到 ABI 之后 + gVisor(runsc) 接入（M2-Q3/Q4）
- **pause/resume 用户 API**（FR-1.4）+ 克隆熵防护复验（M2-Q5）
- **数据面网关**（ADR-22，单机进程内 Rust）+ 一次性 ticket + HMAC 签名 URL + 端口暴露（FR-3.3）+ PTY（M2-Q6/Q7）
- **keepalive 续期端点**（FR-1.2，M2-Q9）；**SLO 裸金属化**（M2-Q10）
- **JS/TS SDK 契约生成版**（从 openapi/proto 生成，砍单预案 §4 已降为契约版）
- 快照加密（ADR-15）为**条件性 stretch**（M2-Q11，M2 末尾/滑期移 M3）

**范围外**（碰了就是范围蔓延）：
- ❌ **集群/etcd/多节点调度、API Key/配额/审计、可观测性全量**（M3）
- ❌ **OCI Runtime 独立形态**（sandlocker-runsc shim，≠ 范围内 M2-Q12「OCI 镜像当 rootfs 来源」）**、持久卷、arm64**（OCI multi-arch index 选择随之为 stretch）**、快照 fork 完整树 GC**（GA）
- ❌ **Kata 后端**（P1+，M3）；**Go 控制面/网关拆分**（M3 闸门复审，见 §4 D3）
- ❌ **JS/TS SDK 手工打磨版**（GA，砍单预案 §4）
- ❌ **域名粒度白名单 FR-3.2b、DNS 审计 FR-3.4**（P1，阻塞项）
- ❌ **完整保留期/版本钉住管理（ADR-16）**：随 M2-Q11 加密条件性推进，滑期与加密一并顺延 M3
- ❌ **S3 远程快照懒加载（userfaultfd 流式取页）**（P2）

## 4. 关键技术决策（承接 ADR + M2 新增）

> 本轮已用决策评审锁定三条主线（D1–D3）；D4 为待验证前置。

- **D1（已定，2026-08-17）：主线 = 骨架优先·债先还。** 顺序：①还 M1 债（jailer-netns live 网络 / allow-network / keepalive）→ ②预热池达池命中 P50 ≤100ms → ③Sandbox ABI + gVisor 两后端 → ④pause/resume + 数据面（网关/PTY/端口）。
  - 快照加密（ADR-15）与 JS SDK 排 M2 末尾，**滑期即移 M3**（stretch，风险隔离）。理由：PRD M2 全量 + M1 债对 2 人 12 周超载，须以「最外层可砍项」吸收滑期，锁死两条硬出口（池命中 P50 + 两后端可切换）。

- **D2（已定，2026-08-17）：第二后端 = gVisor(runsc)。** 用 ADR-14 能力模型显式标注 gVisor **无** `prebake_snapshot`/`pause_resume`（checkpoint/restore 成熟度低），面向短任务高密度场景。
  - 「两后端可切换」由 **ABI 契约测试套件**验收（能力对等而非功能对等）——即两后端跑同一套契约测试、能力差异显式建模，而非要求 gVisor 补齐快照能力。

- **D3（已定，2026-08-17）：语言 = 维持全 Rust 单二进制。** 网关在 M2 单机模式为**进程内模块**（ADR-22 明示单机退化），不拆第三门语言。
  - Go 复审推迟到 **M3 集群拆分**（gw/orchestrator 独立副本、etcd）时再评（延续 M1 D3、ADR-3「M2/M3 闸门复审」）。M2 复用现有 Sandbox ABI 类型，消掉一条跨语言内部契约。

- **D4（待验证前置）：SLO 裸金属 runner。** 承 M0/M1 遗留——W5 前须确认 64C/128G self-hosted dispatch 可用（复用 `bench-density` job 骨架）；不可用则密度/分位数据标注为「裸金属待补」，**不下调口径**（PRD 8.1 注）。

- **D5（已定，2026-08-17）：OCI 拉取机制 = `ureq` + rustls + 手写薄 registry v2 协议。** 在 host 侧 sl-node 的 builder 路径实现（`from = <OCI 引用>` → 拉 manifest/config/layers → digest 校验 → flatten → ext4），MVP 匿名拉公有镜像 + 单架构（x86_64）；私有认证/multi-arch 为 stretch。
  - 理由：守 M1 建立的**全同步 + 手写 HTTP/1.1 + 精简依赖**哲学（现 71 crates、零 tokio/reqwest/hyper）。`oci-client`（原 `oci-distribution`）建在 reqwest→tokio→hyper 之上（异步），会把 crate 数从 71 推到 180–220+ 并引入异步运行时，与架构冲突。
  - 关键权衡：registry 是 **HTTPS**，任何拉取路径都逃不掉 TLS 栈——「手写 HTTP 免依赖」不成立，rustls 是硬需求；但 `ureq` 是**同步**的（内部 rustls，无 tokio），既拿到 TLS 又不破坏全同步架构，落在哲学一侧。
  - 隔离面：OCI 拉取逻辑**只在 host 侧 sl-node 的 builder 路径**，guest musl `sl-envd`（<10MB 目标，PID 1）**不受影响**——不引入任何 guest 侧依赖。

- **ABI 落地策略（M2 新增，架构关键）：先抽象再接第二后端。** 先把现有 FC 后端重构到 `Sandbox` ABI trait 之后（能力位集注册 + `required_capabilities` 创建期校验），**再**接 gVisor——避免「先双实现再抽象」的返工（对齐 ADR-14「能力为 ABI 一等公民」）。W6 抽象、W7 接入、W8 验收。

## 5. 周计划（2 人基线，12 周，T+16 ~ T+28）

| 周 | 主题 | 出口 |
| --- | --- | --- |
| W1 | jailer `--netns` 真 netns 句柄 + veth/NAT 出口通路；把 `nftfw::Sandbox::ensure` 接进 `apply_network_policy` 钩子（仍在 resume 之前） | live gate 通路打通（M2-Q1 起步） |

| W6 | Sandbox ABI 抽象落地 + 能力模型（ADR-14）：FC 后端重构到 ABI trait 之后，能力位集注册 + 创建期校验 | M2-Q3 起步 |

| W8 | 两后端可切换验收（ABI 契约测试套件）+ 能力不齐显式建模（`UNSUPPORTED_BY_BACKEND`） | M2-Q3 / M2-Q4（**硬出口②**） |
| W9 | pause/resume 用户 API（FR-1.4）+ 克隆熵防护 fork/resume 复验 | M2-Q5 |
| W10 | 数据面网关（单机进程内 Rust）+ 一次性 ticket + 签名 URL（HMAC 无状态验签）+ 端口暴露（FR-3.3） | M2-Q6 |
| W11 | PTY 交互式 + 端口暴露端到端 + JS/TS SDK（契约生成版） | M2-Q7 |
| W12 | 收官：快照加密（ADR-15，条件性 stretch，滑期移 M3）+ v0.2~0.4 发布 + M2 出口评审 + M3 闸门 | M2-Q11（条件） / 出口评审 |

**缓冲说明**：**W6–W8（ABI + gVisor）是 M2 最大不确定块**（gVisor checkpoint 成熟度、能力不齐建模第一次合龙）。若滑期：优先保「两后端可切换」的 ABI 契约 + FC 侧不回归；gVisor 若受阻，退到「ABI + 能力显式标注 + 短任务路径」的**最小可切换形态**。快照加密（M2-Q11）为**最外层可砍项**，其次是 JS SDK 打磨深度。

**W3 负载/回退**：W3 塞进了两件事（OCI-as-rootfs + allow-network 构建），其中 OCI 拉取是**新增量**。周内目标锁定 **匿名拉公有镜像 + 单架构（x86_64）**——`from = "python:3.12-slim"` 拉通→ext4→boot 起 Python 即达 M2-Q12 判据。**私有 registry 认证、multi-arch index 选择为 stretch**，滑期即顺延（不阻塞 M2-Q8 的 allow-network 主线，二者可解耦交付）。

## 6. 风险与回退

| 风险 | 回退 |
| --- | --- |
| gVisor checkpoint/restore 不成熟 | 能力模型显式**不承诺** pause/prebake（ADR-14）；「可切换」靠契约测试而非功能对等；退到短任务路径最小形态 |
| 池命中 P50 ≤100ms 依赖 page cache 热 | 分热/冷两档实测；不达标以**热池配置**补而非下调口径（PRD 8.1 注）；热池内存预算显式配置 |
| jailer `--netns` 真网络需特权（CI） | 复用 `dmthin` sudo job / self-hosted runner；rootless dev 档标注为降级（如 M1 占位钩子） |
| 快照加密与 userfaultfd 懒加载冲突 | 分块 AEAD（ADR-15，4MiB 块独立 nonce 支持随机读）；已隔离为 stretch，滑期整体移 M3 |
| 单机网关进程内 → M3 拆独立副本返工 | ticket/验签**现在即设计为无状态**（HMAC 签名 URL、一次性 ticket），钉死接口边界，M3 拆分零语义变更 |
| ABI 重构拖累 FC 现有功能 | 先抽象后接入（D4 ABI 策略）；FC 侧回归由现有 bench 三层 CI（含 M1 全部 Q）守护 |
| OCI 拉取引入重依赖/破全同步架构 | D5：`ureq`+rustls 手写薄协议（同步、无 tokio），拒 `oci-client`（异步、crate 71→180+）；拉取逻辑只在 host 侧 builder，guest musl `sl-envd` 零影响；MVP 匿名+单架构，认证/multi-arch 为 stretch 可砍 |
| 12 周超载 | D1 骨架优先：快照加密 → JS SDK 打磨 → PTY 依次为砍单顺序；每周独立 PR 可验证 |
